# CPG HUB（試作）

退去立会・リノベーション・定期清掃・緊急対応の依頼を、受付から受注、Accessへの引渡まで管理する社員向けアプリの試作です。

## 試作の範囲

- **受付**：依頼の種類、依頼元（大家さん・管理会社など）、物件・部屋・住所、担当。受付すると仮の受付番号が付きます。
- **緊急対応**：症状（水漏れ・給湯器凍結・その他）と、受付からの経過時間。
- **現地確認・立会**：予定日と実施日。退去立会では箇所ごとに家主負担／入居者負担／要確認を付け、小計を出します。
- **見積**：見積書は今までどおりExcelで作り、ここには提出日と金額だけを記録します。
- **結論**：受注・失注（理由）・保留（次に確認する日が必須）。失注と引渡済は毎日の一覧から外れます。
- **Accessへの引渡**：仕事番号はAccessで受注時に振られます。その番号を入れると引渡済になり、以後は読み取り専用です。
- **ToDo**：段階に合わせて自動で作成。期限切れを目立たせ、担当者で絞り込めます。
- **予定・ガント・数字**：月のカレンダー、案件の進み具合の帯、今月の見積決定率と失注理由。

## 使い方マニュアル

- 社員向けの使い方は [manual.html](./manual.html) にあります。アプリのヘッダーの版表示（例「v1.35・10/26更新」）を押すか、「数字」画面の一番下のボタンから開けます。
- **決まり：アプリの見た目や操作が変わるプルリクエストでは、必ず同じプルリクエストで manual.html の該当部分と改訂履歴を更新し、先頭の「このマニュアルは v○○ 用」と最終改訂日を、アプリの版表示に合わせて上げてください。**

## データについて

- このリポジトリのプログラムに入っているのは**架空のサンプルデータだけ**です。実際の案件・取引先・金額は入れません。
- 入力した内容は、その端末のブラウザ（localStorage）にだけ残ります。ほかの人の端末とは共有されません。
- 写真は保存されず、画面を閉じると消えます。
- Googleカレンダーとの連携、データの共有、Access用の項目合わせは、本番版で対応します。

## アプリとして使う

AndroidのChromeで公開ページを開き、メニューの「インストール」または「ホーム画面に追加」を選ぶと、専用アイコンから開けます。

Chromeのメニューで未インストールなのに「インストール済み」と表示される場合は、[インストール専用ページ](./install.html)をChromeで開いてください。ブラウザが`beforeinstallprompt`を通知した場合だけ、ページ内のボタンから確認画面を開きます。同一サイトの別パスにあるアプリを誤認するChromeのメニューとは異なる処理を使います。実機での復旧は別途確認が必要です。ボタンが有効にならない場合、インストール可能とは判断しません。

専用ページは既存のmanifest（id/start_url/scope `/work-hub/`）とアイコンを参照します。別アプリの識別子、Service Worker、キャッシュ、保存データの読み書きは追加しません。受付・ToDoなどの既存プログラムは変更しません。完了表示はブラウザの`appinstalled`通知を受け取った場合だけ行い、確認画面での承諾だけを完了扱いにはしません。

Samsung Internet経由では、Playプロテクトの「古いAndroid向け」警告によってインストールが止まった実機報告があります。保護の解除や、同じサイトを利用するPAPA HUBのデータ削除は行わないでください。

## インストール済みアイコンの更新

アイコン画像を変更したときは、manifest.webmanifest内の各icons.srcとHTMLのアイコン参照に、画像のSHA-256の先頭12桁をvとして付けてください。画像のURLも変えることで、以前の画像との区別ができます。manifest自体のURL、id、start_url、scopeは維持します。

Androidにインストール済みのアイコンは、Chromeのアプリ更新処理で反映されます。ページの再読み込みと同時に変わるとは限らず、更新確認が表示された場合は内容を確認して更新してください。サイトデータの削除やアプリの再インストールは行わずに確認してください。


## v1.34（2026-10-26）

- 予定の月・週・日表示はGoogleカレンダーを表示元とします。HUB内の案件の現調・実施・見積提出・受注の進捗印は追加しません。HUBからGoogleに登録した予定を除外する旧処理を外しています。更新後に一度同期すると、旧版で取得対象から除外されていた予定も読み込めます。
- ToDoは専用画面で管理し、期限が今日以前の未完了分だけ今日の欄にも出します（社員の読み取り専用ToDoも同様）。予定画面のToDoから専用画面を開けます。
- 空室見積は既存のリノベーションと同じ流れ。営繕は受付→見積→施工→請求。営繕の施工中は新しい段階キー `working` で保持し、実施していないAccess引渡日を作りません。入金確認は継続します。社員の種類・段階を正しく表示するには各端末も新版へ更新してください。
- 依頼元の8候補を追加し、自由入力を維持します。
- 保存キー・スキーマ・履歴・未知の項目・同期設定・写真・Google権限・アプリのmanifestを変更せず、既存項目の一括変換はしません。
- 検証方法は `node tests/takeover-browser.cjs`。PlaywrightとChromiumが必要です。テスト用データと模擬Google応答だけを使用します。


## v1.35（2026-10-26）

- 社長のマイカレンダーをカレンダーIDで読み込み対象から除外。社員自身のカレンダー・共有CPG HUBとGoogle登録先は維持します。
- IDのない旧Google予定キャッシュのみ破棄し、新しいキャッシュは保存・読込・描画で同じ除外ルールを適用。表示設定の全OFFを維持し、設定変更や再ログイン前の通信結果を保存しません。
- `node tests/calendar-privacy.cjs` は実際のアプリ全体をNode VMで実行する回帰テスト（DOM・Google応答は架空）。`node tests/takeover-browser.cjs` は既存のChromium/Playwrightテストです。実機Google認証とは別の検証です。

## v1.46（2026-10-29・未公開）

- 緊急対応の受付段階で、日本時間の現地予定日・時刻を保存・変更できます。自動ToDoの期限は予定日になり、未予約の期限・緊急表示は維持します。
- 受注・引渡待ちから、確認画面と必須理由付きで受注後取消を記録できます。元情報・受注日・金額・関連記録を保持し、自動ToDoと日常一覧から外します。再開機能は追加しません。
- 共有の段階キーは既存の `lost`、表示列は「失注」を維持し、旧版で受付扱いになることを防ぎます。予定時刻・取消日時・理由は末尾列に追加します。詳細表示は新版端末が必要です。
- 実装・検証と制限は [docs/case-schedule-cancel.md](docs/case-schedule-cancel.md)。新規テストは `node tests/case-schedule-cancel-browser.cjs`。本候補は未公開です。

本branchは未公開の v1.46（2026-10-29）公開候補です。利用者向けのアプリ・マニュアル表示と版クエリは公開用 v1.46 に準備済みで、公開判断後の版文字列変更は不要です。Draft PR は未mergeで、merge・公開は別途承認が必要です。
