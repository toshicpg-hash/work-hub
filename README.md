# CPG HUB（試作）

退去立会・リノベーション・定期清掃・緊急対応の依頼を、受付から受注、Accessへの引渡まで管理する社員向けアプリの試作です。

## 試作の範囲

- **受付**：依頼の種類、依頼元（大家さん・管理会社など）、物件・部屋・住所、担当。受付すると仮の受付番号が付きます。
- **緊急対応**：症状（水漏れ・給湯器凍結・その他）と、受付からの経過時間。
- **現地確認・立会**：予定日と実施日。退去立会では箇所ごとに家主負担／入居者負担／要確認を付け、小計を出します。
- **見積**：見積書は今までどおりExcelで作り、ここには提出日と金額だけを記録します。
- **結論**：受注・失注（理由）・保留（次に確認する日が必須）。失注と引渡済は毎日の一覧から外れます。
- **Accessへの引渡**：仕事番号はAccessで受注時に振られます。その番号を入れると引渡済になり、以後は読み取り専用です。
- **ToDo**：段階に合わせて自動で作成。期限切れを目立たせ、担当者で絞り込めます。
- **予定・ガント・数字**：月のカレンダー、案件の進み具合の帯、今月の見積決定率と失注理由。

## 使い方マニュアル

- 社員向けの使い方は [manual.html](./manual.html)、社長・全社・GM向けは [manual-admin.html](./manual-admin.html) にあります。アプリのヘッダーの版表示（「v1.49.0・11/2更新」）を押すか、「数字」画面の一番下のボタンから開けます。
- **決まり：アプリの見た目や操作が変わるプルリクエストでは、必ず同じプルリクエストで manual.html の該当部分と改訂履歴を更新し、先頭の「このマニュアルは v○○ 用」と最終改訂日を、アプリの版表示に合わせて上げてください。**

## データについて

- このリポジトリのプログラムに入っているのは**架空のサンプルデータだけ**です。実際の案件・取引先・金額は入れません。
- 入力した内容は、その端末のブラウザ（localStorage）にだけ残ります。ほかの人の端末とは共有されません。
- 写真は保存されず、画面を閉じると消えます。
- Googleカレンダーとの連携、データの共有、Access用の項目合わせは、本番版で対応します。

## アプリとして使う

AndroidのChromeで公開ページを開き、メニューの「インストール」または「ホーム画面に追加」を選ぶと、専用アイコンから開けます。

Chromeのメニューで未インストールなのに「インストール済み」と表示される場合は、[インストール専用ページ](./install.html)をChromeで開いてください。ブラウザが`beforeinstallprompt`を通知した場合だけ、ページ内のボタンから確認画面を開きます。同一サイトの別パスにあるアプリを誤認するChromeのメニューとは異なる処理を使います。実機での復旧は別途確認が必要です。ボタンが有効にならない場合、インストール可能とは判断しません。

専用ページは既存のmanifest（id/start_url/scope `/work-hub/`）とアイコンを参照します。別アプリの識別子、Service Worker、キャッシュ、保存データの読み書きは追加しません。受付・ToDoなどの既存プログラムは変更しません。完了表示はブラウザの`appinstalled`通知を受け取った場合だけ行い、確認画面での承諾だけを完了扱いにはしません。

Samsung Internet経由では、Playプロテクトの「古いAndroid向け」警告によってインストールが止まった実機報告があります。保護の解除や、同じサイトを利用するPAPA HUBのデータ削除は行わないでください。

## インストール済みアイコンの更新

アイコン画像を変更したときは、manifest.webmanifest内の各icons.srcとHTMLのアイコン参照に、画像のSHA-256の先頭12桁をvとして付けてください。画像のURLも変えることで、以前の画像との区別ができます。manifest自体のURL、id、start_url、scopeは維持します。

Androidにインストール済みのアイコンは、Chromeのアプリ更新処理で反映されます。ページの再読み込みと同時に変わるとは限らず、更新確認が表示された場合は内容を確認して更新してください。サイトデータの削除やアプリの再インストールは行わずに確認してください。

## v1.49.1（2026-11-03）空の端末から同期しても共有の記録を消さない

「Googleとまとめて同期」は記録シートに書き込む前に、共有の記録シートの案件・入金・立替の件数を読みます。この端末の記録が空なのに共有に行があるとき、または案件・立替が共有の半分未満（共有4件以上）のときは、何も書かずに止まり、「この端末には記録がありません。共有の記録シートに○件あります」と出します。記録シートに最初につないだときも同じ確認を出します。選べるのは「共有の記録から、この端末に取り込む」と「やめる」だけで、空のまま上書きする操作はありません。

取り込みは共有の記録シートを読むだけです。この端末にない案件・入金・立替・手入力のToDoを足し、記録シートに送るときと同じ形にして共有の行と比べ、一致して端末に保存・読み戻しできたときだけ完了します。失敗・不一致のときは端末も共有も変えません。端末にある記録は書き換えません。受付番号の連番は取り込んだ番号より後から振ります。写真・メモ・症状・住所の詳細は共有にないため戻りません（領収書の写真リンクは保持）。

共有の件数を読めないときも書き込みません。入金・立替・ToDoの表は消してから書かず、余った行を空で上書きする1回の書き込みにしたため、途中で通信が切れても空になりません（案件の表は従来どおり1回の書き込み）。テスト：`tests/empty-device-sync-browser.cjs`。

## v1.49.0（2026-11-02）共通の会社・人選択

ホーム・案件・ToDo・数字・ガント・指示一覧・領収書・会社の動きは、共通の会社・人のドロップダウンで同じ対象を選びます。人は案件と通常ToDoでは担当、リクエストでは宛先、領収書では所有者です。初めは自分。会社と人を選ぶと画面移動・再読込後も引き継ぎます。表示設定は業務DB外で利用設定ごとに保存。未読・権限外を0件や全員へ置き換えません。月・週・日予定も確認済み仕事用の対応設定により同じ対象へ切り替えます。実際の対応ID確認・設定は別途必要です。同期・保存・権限・集計式・書出し操作は変更しません。[実装・検証範囲](docs/view-scope-foundation.md)。

予定の月・週・日と今日のToDoも共通選択に連動します。予定画面の「仕事用カレンダーの対応設定」で、取得済みのGoogle一覧から仕事専用と確認したIDを選び、会社・正規社員を確認して保存します。このブラウザの利用設定別に保存し、他端末へ自動配布しません。未設定・未接続・範囲外・読取失敗は「未取得」で、取得済み0件とは区別します。社員候補は予定未接続でも残ります。「数字」→「Googleカレンダー連携」の読込対象にも選び、予定入力後は本人が同期してください。対応設定だけでは読込対象を増やしません。

複数社を担当し予定ごとの会社が不明なら「会社未特定」を選びます。全社＋本人では表示し、単社へ推測で振り分けません。混在仕事共有は、案件の元記録に保存されたカレンダーID＋イベントID＋受付番号が一意に一致する場合だけ分類します。社員共有表にはイベントIDがないため、他社員の混在予定や旧キャッシュのID欠落は未識別の別件数です。私的予定・未確認カレンダーは表示せず、「全員」でも確認済み仕事用だけです。旧キャッシュで非公開区分を確認できない行は原本を保持し、内容を表示せず「非公開区分未確認」とします。本人が同期して安全属性を再取得してから表示します。混在共有の読取失敗は「追加予定未確認」、取得済みで会社・人物が不明なものは「未識別あり」と分け、予定なしとは断定しません。Google予定・ACL・登録更新処理は変更しません。
