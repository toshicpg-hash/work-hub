# 手入力ToDoの取消（v1.38）

不要になった端末内の手入力ToDoを、完了や入金済みと区別して取り消せます。会社用CPG HUBの機能です。社員宛てリクエストや社員の「見るだけ」の記録を取り消す操作ではありません。

## 操作

1. ほかの古いCPG HUB画面を閉じ、v1.38を開きます。
2. 「ToDo」で、不要になった旧手入力ToDoの「取消」を押します。
3. 確認画面の内容・期限・担当・IDを確認します。「リクエスト」のカードや新しい確認依頼とは別の記録です。
4. 必要に応じて「取消前の控えを保存」を押し、控えを非公開で保管します。
5. 取消理由を確認・入力し、「この手入力ToDoを取り消す」を押します。閉じるだけなら変更しません。
6. 「取り消した手入力ToDo（全期間）」で元の内容、期限、取消日時、理由を確認し、再読み込み後にも残ることを確認します。
7. 会社側へ送る手入力ToDoがある場合は、元の端末で「Googleとまとめて同期」を押してから、閲覧側でも同期します。

取消の状態は `cancelled: true`、取消日時、理由として保存し、元のID・内容・期限・担当・未完了の値は保持します。取消済みの記録は通常の未完了一覧、期限超過件数、予定画面の今日のToDo、Googleの通常のToDo出力から外します。完了済み一覧には移しません。取消後の古い完了ボタンによる操作も受け付けません。

## 保全と競合

取消前に最新状態を読み直し、対象が変わっていたら上書きせず停止します。対象以外の最新の編集は保持します。全文の取消直前控えと対象の前後の記録を、既存の編集履歴用の別キーに保存・読み戻してから、本体へ保存します。本体も全文読み戻して確認します。

控えを保存できない場合は取り消しません。保存後の読み戻しが不一致の場合は繰り返し操作せず、最新状態を確認してください。取消前の控えには他の案件や設定も含まれ、画像本体は含まれません。非公開で保管し、ストレージ初期化や古いバックアップの全体上書きは行いません。既存の資料・画像・履歴を削除しません。

編集履歴から以前の文面を戻しても、取消状態は解除しません。取消と完了は別の状態です。完了済み・リクエスト・自動ToDo・Google由来の記録は、この取消機能では変更しません。

## 社員宛てリクエストとの区別

同期で元の「指示」台帳を取得できた場合、会社側のリクエスト表示はその最新の状態・内容・期限に基づきます。社員の古いToDo出力が残っていても、取り消した依頼を再表示したり、未完了へ戻した依頼を古い金額・日付で二重表示したりしません。元台帳を含まない古いキャッシュは、前回取得分として保持し、次の同期で更新します。

リクエストの状態を直す場合も既存IDを照合し、新しい行を重ねて作らないことが重要です。手入力ToDoの取消はリクエストの取消や復元を自動実行しません。案件・Googleカレンダーの予定も変更しません。

## 検証

```sh
node tests/manual-todo-cancel.test.cjs
node tests/manual-todo-cancel-browser.cjs
```

ブラウザテストはPlaywrightとChromiumを使用します。`CHROMIUM_PATH`と`CPG_CANCEL_ARTIFACTS`でブラウザと結果保存先を指定できます。会社の実データは使わず、Google通信を差し替えて取消・履歴・再読込・同期表示を確認します。既存の案件編集、手入力ToDo編集、予定、カレンダープライバシー、領収書のテストも継続します。
