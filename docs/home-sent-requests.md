# v1.48.1 管理側のタスクリクエスト

基準main: bf2b45dc5c265f1d48429c0c384bcd7848761ebe（PR67）。

ホームの管理側タイルと、既存の指示一覧のホームからの表示だけを変更。社員のホームとToDoから開く指示一覧は従来どおりです。同期・保存・認証・権限・完了報告の処理は変更しません。

I系は既存adminOrderAddが社長だけに提供され、7列に作成者はありません。この既存契約で社長の送信分とします。全社・GMにはI系を自分の送信分として数えません。社長は既存読取データの全B系を含め、I系および社長GmailのB系を社長の内訳とします。全社・GMだけはB系の出した人Gmailと本人を照合し、自分宛てを除外して既存canSeeで社員範囲を限定。社長の一覧は作成者Gmailで切り替え、同名の作成者も別に扱います。全社＋gmCo=CPは全社、role=GMは担当会社のみです。

社員のシートID（I系）／指示箱ID（B系）と指示IDで重複をまとめ、取消＞完了＞未完了。B系の完了は既存boxStateと報告情報を使用。期限切れは日本時間の今日より前、5日以内は今日から+5日まで。+6日・期限なしは未完了総数と一覧に残します。読取失敗・未読込・未知状態は確認できた分の件数である旨を表示。件数は最後に読み込んだ記録であり、最新状態は既存同期で読み直します。

## 検証

`node tests/home-sent-requests-browser.cjs`：8シナリオ群。社長・社員・全社＋CP兼任・CP限定GM、本人送信9件／期限切れ1件に加えて社長は他者B系を合算、今日／+3／+5／+6／期限なし、LA端末時刻でのJST日境界、I/B共存と重複、取消・完了優先、他者送信・自分宛て除外、会社範囲、ホームから指示一覧、全文開閉・閲覧専用、保存データ不変と既存キャッシュ再読込、未読込注意を合成データで検証します。既存home-tilesテストは管理側の遷移先だけrequestsへ更新。

I系には個別作成者がなく、社長専用という既存契約以上の帰属判定はできません。データ形式を増やす変更や移行は行いません。ワンタイムボードの保全ブランチは対象外です。
