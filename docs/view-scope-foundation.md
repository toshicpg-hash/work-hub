# 共通表示対象の基盤（開発保全）

基準: main `5fcae998bbc831c14119da0547bccd0bfdeadae7` / v1.48.7。
ホーム・案件・ToDo・数字・ガント・指示一覧・領収書・会社の動きは、共通の会社・人のドロップダウンで同じ対象を選びます。人は案件と通常ToDoでは担当、リクエストでは宛先、領収書では所有者です。初めは自分。会社と人を選ぶと画面移動・再読込後も引き継ぎます。Google予定は従来の参考表示のまま共通選択対象外。会社カレンダー統合を完了したという意味ではない。

- `view-scope.js` は表示設定のみ。account / record sheet / viewer list の組で別のlocalStorageキーを使う。業務DB、Google、権限への書込みはない。
- 初期は自分。人物はsheetID。候補は呼出側の既存権限判定を必須とし、欠落・例外は候補にしない。同一sheetIDの重複も候補にしない。同名はIDを添えて区別する。
- 会社変更で選択人物が候補外になっても、全員へ自動変更しない。保存値不正、権限外、未読込、読取失敗を区別する。保存後の読み戻し失敗を成功としない。
- 単体10群、模擬画面ブラウザ3群、実アプリ接続11群。実アプリでは会社/人、旧名の根拠、ホーム・ToDo・予定の今日ToDo・ガント・指示・会社・領収書・数字、役割切替と保存分離、未読/権限外、業務DB/自動ToDo/共有出力不変を確認。全接続画面で390px通常、360px実フォント150%、820×900を検証。実Google・実機は含まない。
- 案件を正本にする予定UIは新方針で中止。未実装なので該当差分はない。会社Googleカレンダー正本の実装は設計確認後。現行の手動登録・更新は未変更。
- ワンタイムボードは別branch保全のまま。新しい経理role・閲覧拡大も未実装。

## 会社Googleカレンダー設計の未確定事項

1. 他人の予定を編集できないことを優先し、個人別の仕事用カレンダー（私的カレンダーとは別）を集約する案を検討中。会社別3つという固定設計は保留。ただし実IDと人別ACL・配布方式は未確定で、会社カレンダーの設定実装はまだ行わない。表示名、イベント件名、住所から会社・担当を推測しない。primaryや既存個人カレンダーを初期値にしない。所有者は本人アカウントの方向。正しい既存ID、人別ACL・管理担当、設定の正本・配布方法は未確定。
2. Calendar ACLのwriterはカレンダー全体の予定を書ける。作成者だけ編集というACLはない。HUBのUI制限ではGoogleアプリによる他人の予定編集を防げない。reader＋認可された仲介サービスの方式なら別設計・認証・運用が必要で、現在の静的アプリの小変更ではない。
3. extendedProperties.privateはcalendarId/eventIdごとのコピーに属し、登録者だけに秘密という意味ではない。同じ共有calendarにアクセスできる編集者から秘匿する設計には使えない。visibility:privateもwriterには詳細が見える別の属性である。
4. metadata案はschemaVersion・会社・元記録を特定する識別子・案件ID・担当sheetID・必要な担当Gmail。受付番号だけでは社員間で衝突する。金額・入金・秘密の住所は入れない。編集者が書換可能なmetadataを案件の閲覧認可として信用しない。HUBで実際の案件閲覧権限を独立確認する。
5. Googleアプリで直接作った予定にはmetadataがない。作成者と担当者は同義ではない。担当不明の扱いは明示し、推測割当しない。一般社員にも同社予定を見せる新方針と、担当不明を社長/全社だけとする既往方針の適用範囲は確認が必要。
6. Googleを正本にしながらHUBの変更を自動送信する場合、Google側で変更された日時をどちらに反映するか・競合時の処理・取消/削除・会社変更/担当変更・再送重複防止を定義する必要がある。既存gRegisterは手動・終日であり、この仕様は未実装。

実アカウント作成、カレンダー作成/共有、実予定登録更新、権限・認証変更は実行していない。

旧テストの更新は、初期が全員である前提を明示的な全員選択に変更し、権限fixtureに正式な社員一覧を用意したもの。会社未設定を所属会社で補完する旧期待値は、新方針に合わせて除外へ変更する。集計式自体は変更しない。

表示設定のaccountキーは既存の社長／見る人用設定を使用する。一般社員はGoogleログインメールを新たに取得・保存せず、既存の本人記録sheetIDで区別する。別人が同じブラウザ・記録設定を使うことを認証で防ぐ機能ではない。

案件詳細・新規受付・領収書入力では選択を保持するだけで変更欄を出さない。未保存の入力を再描画で消さないため、表示対象の変更は一覧画面で行う。本人記録sheetIDが未設定なら「自分」はこの端末の記録を指し、正式な社員への推測対応は行わない。


## 表示の境界と回帰確認

- ToDoは表示専用のscopeTodosを使い、genTodos・共有出力は全件の既存処理を保持。会社未設定の案件は推測しない。案件に結び付かないToDo/リクエストの会社は根拠のある担当/宛先プロフィールの所属による。
- 領収書は所有者sheetIDと明示会社で選択。方法フィルターは残す。自分の編集可能記録と共有の見るだけ記録を混ぜて保存しない。旧rScope表示設定に依存しない。
- 社長設定は古いviewEmailのGM役割より優先。GM→社長→GM、全社+gmCo、利用設定ごとの選択分離を検証。
- 全体の期限切れToDo/緊急/失注日未入力/未読と端末同期注意は選択外でも表示。会社の同期状況一覧も閲覧範囲全体と明記。
- 旧画面別フィルターを使うテストは共通ドロップダウンへ置換。初期全員の前提は明示的な全員選択にする。通常編集・完了・取消・共有の安全性検証は保持。

予定画面の今日のToDoも共通選択に連動します。Google予定は会社・担当の根拠がないため選択対象外の参考表示を維持します。

全43スクリプトは各 `node tests/<ファイル名>.cjs` で実行。最終コミットの結果はPR用報告で記録する。390/360/820の画像は `docs/preview/scope-*.png`（合成データ）。文字150%は全要素のcomputed font-sizeを測定して1.5倍に設定し、再描画ごとに復元・再適用。deviceScaleFactorの代用ではない。
