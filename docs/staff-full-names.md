# 氏名対応の設計・実装記録

v1.48.7。GM修正PR73を基礎にする依存PR（base `codex/gm-share-scope`）。GM差分を氏名のレビュー差分に混ぜない。基準GM headは `40c10ed60765532ef9790cafb597d99f87063d8d`。mainへの公開は別承認。

## 調査と設計

- 現在の正規名候補は社長の社員一覧の氏名、閲覧者用一覧の氏名、社員本人の領収書設定氏名。担当の保存値は姓・略称・フルネームが混在する。
- 現行コードの「同姓なら全社の人、なければ一覧の先頭」という推測は廃止する。正規名・旧登録名・変更前の氏名に一致する人が一意なときだけ解決する。旧略称は根拠となる登録名と所有シートIDを使い、衝突は未特定のまま残す。根拠のないフルネームを作らない。
- 正規氏名変更は社長の既存管理権限に限定する。社員一覧のシートIDを識別子とし、過去案件/ToDo/履歴の担当値は一括置換しない。旧登録名と正規表示名を分離する。
- 管理者の確認操作後に、社員一覧の「社員氏名履歴」へ追記する方式を採る。既存社員列は維持し、旧登録名を残す。社員本人と閲覧者への正規名・旧名の伝達は、権限のある既存シート内の同名タブへ履歴を追記する。新しい共有権限やOAuth scopeは追加しない。
- 初回表示での移行はしない。変更前後・対象シートを確認し、中止で不変。履歴と送付先の読戻しまで確認できたものだけ成功扱いにする。通信結果不明は同じ変更IDを再読し、未確認のまま盲目的に新しい変更を重ねない。
- 管理者の登録名がまだ姓/略称なら、勝手に正式名へ直さず、管理者が確認して入力する。社員本人の既存設定も、正規名情報が未取得ならそのまま表示する。

実社員一覧・実データ・実権限・試用メールは操作しない。

## 保存と互換性

- 保存先：社長の既存「CPG HUB_社員一覧」、対象本人の既存記録シート、既存の「見る人用一覧」（存在するとき）の `社員氏名履歴` タブ。列は `変更ID / 段階 / 記録JSON`。段階は `intent`（変更予定）と `confirmed`（保存確認済み）。JSONは対象シートID、旧登録名、変更前後の氏名、旧名、UTC ISO日時を含む。画面の履歴はJST表示。
- 初回作成は社長の「正規氏名」確認後だけ。後から閲覧者用一覧が作られた場合は、管理者が共有変更を確認した操作中に確定済み氏名履歴を複製する。通常の表示・同期ではタブを新設しない。
- 既存のSheets/Drive権限だけを使う。氏名操作からpermission APIの変更は行わない。社員一覧の既存列の順序・旧登録名、案件・ToDo・既存履歴の担当値は変更しない。読み取り専用の合成案件IDと集計の重複識別だけは、可変の氏名から元シートIDへ変更し、同姓同名を混同しない。
- 本人の通常同期は自分の氏名履歴を読み、表示用設定を保存する。社長/閲覧者も既存一覧読取り時に履歴を重ねる。旧版は新タブを無視し、旧名で表示する。旧版の通常同期がこのタブを消す処理はない。旧版からの管理・同時編集は避け、新版に更新して使う。
- 名前履歴は既存ファイルの閲覧者から読める。本人は自身の記録シートに既存のwriter権限があるため、Google上で氏名タブを直接変更できる。履歴は暗号署名された改ざん防止記録ではない。HUBの正規氏名編集UIは社長だけに限定するが、既存Drive権限を強める機能ではない。
- Sheets間のトランザクションやロックはない。直前の社員一覧/接続先/名前履歴を照合し、変化を検出したら停止する。確認後の完全な同時書込みまでは排除できないため、管理操作は1端末・1タブずつ。途中で本人・閲覧者にだけ反映する場合がある。masterの未確認intentを保ち、同じ名前の再試行で同じ変更IDを読み戻し、不足分だけ追記する。他の新しい名前への変更は未確認分の解消まで停止する。
- 同じ正規名の人はGmail/シートID付きラベルで区別する。旧キー自体が重複する場合、保存値を増設して移行せず、該当する新規担当選択肢を無効にする。既存の曖昧なキーは元のまま表示する。本人シートを特定できる読取りではその持ち主を使う。
- 過去の指示の「出した人」文字列、作成済み精算書・提出記録、本人の旧氏名設定、Driveファイル名は一括変更しない。新しく指示を出すときの表示は正規名を使う。正規名の根拠がない人物は推測でフルネーム化しない。

## 氏名レビュー対応

- 正規名・旧登録名・旧aliasを空白正規化して照合する共通 `matches` を、新規担当選択の無効化にも使用。完全な氏名の候補が複数なら本人シートのownerでも選ばない。従来の姓だけの記録は、正規名との完全一致がなく、所有元が候補の1人と分かる場合だけ従来どおり所有元で表示する。空欄担当は元シートの持ち主を使う。実データのキーは置換しない。
- 新しい履歴は `previousId` に直前の確定変更IDを記録する。確定行の到着順ではなく、一意な変更チェーンを辿って表示する。先行変更がまだ未確認なら新しい表示を適用せず、未確認として残す。分岐・循環・前後不一致は推測せず停止。遅延した古いconfirmedの追記でも巻き戻らない。旧形式で複数の独立した変更があり順序を証明できない場合も自動で順序を推定しない。
- 社員の表示用氏名のローカル保存失敗は再throwし、その後の案件・入金・立替・ToDo・情報の書込みを進めない。
- 担当バッジは高さ自動・明示line-height・小さな角丸と余白で複数行を囲む。文字150%でRangeの各文字行の上下左右が枠内にあることと、角丸より左右余白が広いことをassertする。文字を切るoverflow隠しは使わない。
- 追加検証：正規名と他人の登録名の衝突/空白差/旧alias、本人ownerでも誤割当しない、実コピー途中失敗→後続確認→古い確定の遅着→再コピー、氏名保存失敗後remote書込み0件。
