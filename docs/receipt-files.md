# 領収書を保存済みPDF・画像から登録する（v1.42）

CPG HUB専用の変更です。PAPA HUBには影響しません。

「領収書」→「＋ 領収書を登録」→「ファイルから選ぶ」で、保存済みのPDF・画像を選びます。Androidのファイル選択画面でGoogle Driveが利用できる場合は、Driveに保存した原本を選べます。選択画面でDriveが出るかどうかは端末側の設定にも依存します。Google認証の権限追加はありません。Drive側の原本を書き換えません。

PDFは「PDFを開く」で確認できます。PDFを画像として読み込んだり、ページを自動描画したりしません。画像はプレビューと原本へのリンクを表示します。いずれも「原本を保存」から取り出せます。

## 保存と失敗時の動作

- 入力値を先に固定し、保存中の操作と二重送信を防ぎます。
- PDF・画像の内容から形式を確認し、原本のバイト列・元のファイル名・拡張子情報を保持します。画像の縮小・再圧縮は行いません。
- 同じ原本の再選択は重複して追加しません。不正な形式が混じる選択は、その選択分全体を追加せず、既存の入力と選択を残します。
- 既存のIndexedDB `workhub_receipt_photos` / `photos` を使用します。既存の写真キーや保存構造の移行はありません。
- 保存前の本文全体と編集前の記録を、操作IDごとの控えとして同じ端末のIndexedDBへ残します。既存の写真原本は、添付一覧から外した場合もこの変更では消去しません。
- 新しい複数添付は一つのトランザクションで保存し、一枚だけ成功した状態を本文へ反映しません。添付を小さなチャンクで読み戻し、原本と一致することを確認します。
- 本文は最新状態を読み、同じ領収書が変更されていたら停止します。別の記録の変更は取り込んで保持します。本文の保存直前にも最新状態を確認し、保存後の完全な読み戻しが一致してから成功表示します。
- 失敗時は入力と選択中の添付を残します。本文が未保存と確認できた場合、同じ操作ID・添付キーで再試行でき、二重登録しません。本文の保存結果が不明な場合は入力を固定し、「保存状況を確認」から同じ操作を再確認します。新しい領収書を重ねて作りません。
- 初期化、サイトデータ・キャッシュの削除、アプリ再インストールを手順の前提にしません。

## 共有・書き出し

「Excelと添付を送る」では、PDFは `.pdf` と `application/pdf`、画像は対応する形式で原本を渡します。Excelの列構成は変更しません。原本が見つからない場合は不完全な共有を行わず停止します。共有をキャンセルしても登録済みの本文・添付は変更しません。ファイル共有に対応しない場合はExcelと各添付の保存リンクを表示します。

既存のGoogle Driveへの控え送信もPDFの形式と内容を保ちます。この変更でDrive全体を検索する権限や新しい共有先は追加しません。

## 検証範囲

`tests/receipt-files.test.cjs` と `tests/receipt-files-browser.cjs` は合成データ専用です。形式判定、PDFを開く・原本ダウンロード、画像混在、選択キャンセル・再選択、保存と再読込、容量不足、途中失敗、保存結果未確認、競合、二重送信、共有・書き出しと既存データ保持を検証します。

ブラウザー検証は320/390/822pxのChromiumで行います。実際のAndroid端末のDrive選択画面や、報告された「撮影後にホームへ戻る」エラーの原因を確認したことにはなりません。カメラ起動や自動PDF描画を避ける変更であり、端末のメモリ不足が原因、または今回の変更でその現象が必ず解消するとは断定しません。
