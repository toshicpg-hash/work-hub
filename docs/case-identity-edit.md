# 登録済み案件の物件名・号室の修正（v1.37）

案件を入力した本人の端末で、同じ受付番号のまま物件名・号室を訂正します。削除や再登録は不要です。

1. CPG HUBをv1.37へ更新し、「案件」で対象を開きます。
2. 案件名の下の「物件名・号室を直す」を押します。
3. 必要に応じて「編集前の控えを保存」で控えを保存します。
4. 物件名・号室を直し、「変更を保存」を押します。号室は文字列で保存し、先頭の0や英字も保持します。戸建てなどは空欄にできます。
5. 再読み込みして修正が残ることを確認し、「Googleとまとめて同期」を押します。
6. 会社側でも「Googleとまとめて同期」を押し、社員の最新の記録を読み込みます。

変更するのは物件名・号室だけです。受付番号、進捗、日付、見積、請求、入金、履歴、Google予定の識別情報、領収書との紐付け、設定を保持します。予定・Google Sheetsへの書き込みや新規案件の作成は、編集保存の処理では行いません。Google Sheetsの既存同期用データには、次の同期で同じ受付番号の訂正後の名前・号室が出ます。

社員の「見るだけ」の案件では修正できません。社長画面の表示だけを変えると元の記録と食い違うため、入力した社員の端末で修正して同期します。引渡後・施工中・完工・請求済・入金済の案件は、既存の読み取り専用方針を維持します。Accessや登録済みGoogle予定のタイトルは自動更新しません。

## 控えと競合

保存前に端末の最新データを読み直し、対象が編集中に変わっていれば上書きせず入力を残します。対象以外の最新の追加・編集は保持します。保存直前にも変化を確認します。

変更直前のデータベース全文と対象の前後の記録を、端末内の別の履歴キーへ保存・読み戻してから本体を更新します。本体も読み戻して照合します。空き容量が不足し、控えを残せない場合は修正保存を止めます。元の履歴を自動削除しません。

「編集履歴（この端末）」から以前の物件名・号室を編集欄に読み込めます。確認して保存すると新しい履歴を残し、進捗や金額を昔へ戻すことはありません。保存できない場合は「入力内容を控えとして保存」で入力を保全してください。端末の初期化・全体の古いバックアップへの巻き戻し・案件の削除再登録は行いません。

履歴と控えには端末内の案件・設定が含まれます。非公開で保管してください。画像本体は別のIndexedDBにあり、JSONの控えには含まれません。画像は修正処理で変更しません。

古い版の画面は新しい競合防止に協力できません。実データの編集前に、同じブラウザのほかのCPG HUB画面を閉じて最新版を開いてください。Web Locks対応時は手入力ToDoの編集・案件名修正・まとめて同期を同じロックで順番に処理します。非対応時は複数画面での同時操作を避けます。

## 検証

```sh
node tests/case-identity.test.cjs
node tests/case-identity-browser.cjs
```

ブラウザテストはPlaywrightとChromiumを使用します。`CHROMIUM_PATH`でブラウザ、`CPG_CASE_ARTIFACTS`で結果保存先を指定できます。会社の実データを使わず、Google通信を差し替えます。既存の手入力ToDo・カレンダープライバシー・予定・案件・領収書のテストも継続して実行します。
