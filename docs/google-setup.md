# CPG HUB と Googleカレンダーをつなぐ手順（社長用）

CPG HUB は PAPA HUB と同じ「Googleとまとめて同期」の仕組みで Googleカレンダーとつながります。
Google の入り口（Google Cloud のクライアント）は PAPA HUB と同じものを使うので、新しく作る必要はありません。
パソコンのブラウザで、toshi.cpg@gmail.com にログインして作業してください。

## 1. 専務がログインできるようにする（Google Cloud）

1. https://console.cloud.google.com を開き、上の「プロジェクト」で PAPA HUB に使っているプロジェクトを選ぶ
   （クライアントID が `766726293537-…` のプロジェクトです）
2. 左のメニュー「APIとサービス」→「OAuth 同意画面」（新しい画面では「Google Auth Platform」→「対象」）を開く
3. 公開ステータスが「テスト中」なら、「テストユーザー」の「＋ ユーザーを追加」で
   `only.1.mybrand@gmail.com`（専務のGmail）を追加して保存
   （会社のメール h-kuroki@cleanpapa.com はGoogleアカウントではないので使えません）
   （「本番環境」になっている場合は、この作業はいりません）
4. 「認証情報」（または「クライアント」）で `766726293537-…` を開き、
   「承認済みの JavaScript 生成元」に `https://toshicpg-hash.github.io` があることを確認
   （PAPA HUB と同じ場所なので、入っているはずです。なければ追加して保存）

## 2. みんなで使う「CPG HUB」カレンダーを作って専務と共有する（Googleカレンダー）

社長の「CPG」カレンダーは社長個人の仕事用なので、共有しません。会社みんなで使う共有カレンダー「CPG HUB」を別に作ります。

1. https://calendar.google.com を開く
2. 左の「他のカレンダー」の「＋」→「新しいカレンダーを作成」
3. 名前に `CPG HUB`（半角、CPG と HUB の間に空白）と入れ、タイムゾーンは「(GMT+09:00) 日本標準時」で「カレンダーを作成」
4. 左の「マイカレンダー」に出た「CPG HUB」→「︙」→「設定と共有」
5. 「特定のユーザーまたはグループと共有する」→「ユーザーやグループを追加」
6. `only.1.mybrand@gmail.com`（専務のGmail）、権限は「予定の変更」を選んで「送信」

HUB の案件画面の「Googleカレンダーに登録」は、最初からこの「CPG HUB」に登録します（予定画面では「共有」というラベルで表示）。
社員が増えたら、同じ手順で「CPG HUB」を共有します。

※ 専務の予定を社長の HUB に出すには、専務から社長へカレンダーを共有してもらいます（専務にはメールで依頼済み）。
共有されると、社長のカレンダー一覧に `only.1.mybrand@gmail.com` が出てきます。HUB では「黒木」と表示します。

## 3. 社長の HUB で確かめる

1. CPG HUB を開き直し、左上が「v1.13」以降か確認
2. ホームの青いボタン「Googleとまとめて同期」を押す
3. toshi.cpg@gmail.com を選び、カレンダーへのアクセスを許可
4. ボタンの下に「✓ Googleにログイン」「✓ カレンダー一覧」「✓ 予定の読み込み」と出れば成功
5. 予定画面で、CPG HUB と黒木の予定が出ているか確認。社長のマイカレンダーは読み込みません。社長個人の「CPG」は、従来どおり初期表示には含めません。
6. 「数字」画面の下「Googleカレンダー連携」で、表示するカレンダーと、案件の日程を登録するカレンダー（最初は CPG HUB）を選べます

## 4. 専務の HUB で確かめる

専務に「設定が終わった」と連絡し、専務のスマホで同じように「Googleとまとめて同期」を押してもらいます。
`only.1.mybrand@gmail.com` を選んで許可すれば、専務自身のカレンダーと CPG HUB カレンダーが出ます（社長の CPG は出ません）。

## うまくいかないとき

| 出た表示 | 原因と対処 |
|---|---|
| 「このアプリはGoogleで確認されていません」 | 社内用なので問題ありません。「詳細」→「移動」で進む |
| 「アクセスをブロック」「403 access_denied」 | 1-3 のテストユーザーに、その人のアドレスが入っていない |
| 「redirect_uri_mismatch」「origin」 などのエラー | 1-4 の JavaScript 生成元が入っていない |
| 「Googleの画面を開けませんでした」 | ブラウザのポップアップを許可する |
| 予定の読み込みで「読めないカレンダーがあります」 | そのカレンダーの共有がまだ、または権限が足りない |

## 決まりごと

- ログインの情報（トークン）はスマホのメモリにだけ置き、保存しません。アプリを開き直したら、もう一度「Googleとまとめて同期」を押します（PAPA HUB と同じ）。
- 最後に読み込んだ予定（件名・日時・場所。非公開の予定は「予定あり」のみ）は、開き直してもすぐ見られるよう、その端末に30日まで残します。
- 案件の日程は、案件の画面で「Googleカレンダーに登録」を押したときだけ登録します。自動では登録しません。
- 登録するのは件名・日付・住所・受付番号・依頼元・担当だけです。メモや症状は送りません。
- 日付を変えたら、案件の画面の「カレンダーの予定を更新」で同じ予定を書き換えます（二重に登録しません）。

## プライベートな予定の扱い（社員・専務）

- 各自の HUB には、その人が自分の Google でログインして見られるカレンダーだけが出ます。各自のカレンダーは、本人が共有しない限り、ほかの人の HUB には出ません。
- 社長などに自分のカレンダーを共有している場合でも、Googleカレンダーで「非公開」にした予定は、カレンダーの持ち主以外の HUB では「予定あり」とだけ表示し、件名と場所は出しません。
- 仕事でみんなに見せる予定は「CPG HUB」カレンダーに入れます。


## v1.35：社長のマイカレンダーを読み込まない

- `toshi.cpg@gmail.com` のカレンダーは、社長本人・社員のどちらでログインしても読み込みません。「自分」「社長」といった名前ではなくカレンダーIDで判定します。社員自身のprimaryカレンダーは除外しません。
- 古い表示設定にそのIDや社長の `primary` が残っていても取り除きます。全部OFFの設定は全部OFFのままです。
- 旧版のGoogle予定キャッシュはIDがなく判定不能なので初回に破棄します。会社や社員の予定は再同期してください。新版のキャッシュは保存・読込・描画時にIDで確認します。
- 案件・ToDo・領収書、Googleへの登録先、Google側の予定・共有権限、PAPA HUBの保存データは変更しません。
- 各端末で新版を開く必要があります。開いたままの旧版やオフラインの旧HTMLは、再読み込みするまで旧動作のままです。
- 検証：`node tests/calendar-privacy.cjs`（Node VM上で実際のアプリ全体を実行、DOM・Google応答は架空）。既存のブラウザ回帰テストは `node tests/takeover-browser.cjs`（Chromium/Playwrightが必要）です。実アカウントの認証・共有権限は別途実機で確認してください。
